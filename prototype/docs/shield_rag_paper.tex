\begin{abstract}
Retrieval-Augmented Generation (RAG) grounds Large Language Models (LLMs) in external data sources, but exposes query semantics and retrieved document embeddings to untrusted hosting servers. Existing privacy-preserving frameworks secure vector indexing but leave structured knowledge graph links and transient self-attention states vulnerable to information leakage. We present SHIELD-RAG, a privacy-preserving hybrid RAG architecture operating entirely on encrypted representations. SHIELD-RAG integrates searchable Inner Product Functional Encryption (IPFE) with three fine-grained access-control engines: Sensitivity-Embedded IPFE (SE-IPFE) for hierarchical clearance verification, Query-Derived Cryptographic Scope (QDCS) for category domain restriction via orthogonal subspace projection, and Progressive Onion Decryption (POD) for multi-hop graph path containment. We evaluate the system on a corpus of \NumDocs\ real documents using S-BERT semantic embeddings. The experimental results demonstrate that SHIELD-RAG achieves a \HitAtTen\ Hit@10 retrieval accuracy, matching plaintext RAG quality within 2.0\%, while enforcing access clearances and domain scopes with \EnforcementSuccess\ success. We report database matching times of \AvgSearchLatency\ for SE-IPFE and \PodSearchLatency\ for POD, establishing a practical trade-off between semantic search utility and end-to-end data confidentiality.
\end{abstract}

\section{Introduction}
Retrieval-Augmented Generation (RAG) has established a standard for grounding Large Language Models (LLMs) in external knowledge repositories. By dynamically retrieving relevant document chunks during inference, RAG overcomes the static context limits of pre-trained parameters and reduces factual hallucinations. However, querying external vector stores and structured knowledge bases introduces severe privacy risks. Sensitive user queries, document embeddings, and metadata are exposed to intermediate orchestration servers, third-party database hosts, and model-serving infrastructure. This threat surface enables reconstruction attacks (such as embedding inversion) and knowledge poisoning, compromising proprietary enterprise data. In standard implementations, these vector representations can be mapped back to their original text tokens using trained inversion decoders, resulting in complete exposure of private data.

Conventional privacy-preserving RAG frameworks face a trade-off between cryptographic overhead and search utility. Perturbation-based approaches like differential privacy degrade retrieval accuracy by adding statistical noise to embeddings. Conversely, cryptographic schemes using Fully Homomorphic Encryption (FHE) or Secure Multi-Party Computation (SMC) preserve accuracy but introduce severe latency penalties, making online LLM inference impractical. Furthermore, secure retrieval methods focus on protecting the database index search. They assume that knowledge graph topology, multi-hop traversal paths, and post-retrieval self-attention states remain visible to the server, creating a transient exposure window. For instance, when traversing a knowledge graph, the sequence of node accesses reveals structural relations and entity connections, exposing sensitive enterprise schemas even if individual node payloads are encrypted.

Prior secure RAG frameworks, such as CipheRAG \cite{zhou2026efficient}, use searchable Inner Product Functional Encryption (IPFE) to compute similarity scores over encrypted embeddings. Although this protects baseline vector search, it lacks fine-grained access control to enforce security clearances. In addition, it does not support dynamic boundary enforcement to restrict queries to permitted categories, nor does it secure the structural links during graph traversal. At the generation stage, unencrypted embeddings must be loaded in plaintext into the LLM context window, exposing sensitive transient contexts to the model host.

We address these gaps by introducing SHIELD-RAG, a unified privacy-preserving hybrid RAG architecture. SHIELD-RAG operates semantic search, structured graph traversal, and generation-time attention masking entirely over encrypted representations. The architecture introduces three core engines. Sensitivity-Embedded IPFE (SE-IPFE) encodes user clearance level gates directly into Paillier ciphertexts. Query-Derived Cryptographic Scope (QDCS) restricts retrieval boundaries by projecting out-of-scope document matches onto orthogonal complements. Progressive Onion Decryption (POD) wraps embeddings in nested encryption shells, peeling them sequentially based on graph traversal depth.

We evaluate the prototype over a corpus of \NumDocs\ Wikipedia documents using real SentenceTransformer (\texttt{all-MiniLM-L6-v2}) embeddings. The contributions of this work are as follows:
\begin{enumerate}
    \item We design a secure hybrid RAG architecture combining encrypted semantic retrieval with three fine-grained cryptographic access control backends (SE-IPFE, QDCS, and POD).
    \item We implement a bounded-decoy graph traversal mechanism that hides the true navigation path among $K-1$ semantically similar decoys, preventing server-side traversal pattern leakage.
    \item We present a secure attention gateway using PyTorch attention hooks to apply relation-based decryption subkeys, preventing unauthorized transient contexts from influencing LLM generation.
    \item We perform an empirical evaluation measuring key generation, database encryption, retrieval search, and gateway decryption latencies, demonstrating that SHIELD-RAG achieves a \HitAtTen\ Hit@10 accuracy while maintaining complete data confidentiality under the defined threat model.
\end{enumerate}

\section{Related Work}
\subsection{Retrieval-Augmented Generation}
Retrieval-Augmented Generation (RAG) integrates pre-trained language models with external text repositories to ground responses in factual context. Standard RAG segment documents, generate semantic vectors via neural models, and query vector indexes using nearest-neighbor metrics. Despite their utility in reducing hallucinations, these systems expose sensitive document content to intermediate databases. Standard dense retrieval techniques utilize cross-encoders to align query and context vectors, which yields complete metadata leakage on semi-trusted servers. Lightweight custom rerankers reduce local on-premise execution latencies but do not encrypt vector representations during indexing \cite{tua2026lightweight}.

\subsection{Privacy-Preserving Retrieval}
To protect data during similarity computation, searchable symmetric encryption allows queries over encrypted files. Fully Homomorphic Encryption (FHE) supports arbitrary mathematical operations on ciphertexts but introduces prohibitive CPU and memory latencies. Oblivious Transfer (OT) provides query privacy but requires multi-round interactive communication. Functional Encryption (FE), specifically Paillier-based Inner Product Functional Encryption (IPFE), offers a non-interactive, single-round alternative. IPFE allows an untrusted server to compute dot products directly over ciphertexts to output similarity values without learning the underlying vector coordinate values. Differential privacy provides faster search times but introduces statistical noise that degrades semantic retrieval accuracy.

\subsection{Secure RAG}
State-of-the-art secure RAG frameworks utilize IPFE over Paillier composite moduli. For example, CipheRAG \cite{zhou2026efficient} combines IPFE with Asymmetric Locality-Sensitive Hashing (ALSH) to perform sub-linear signature matching, decrypting retrieved tokens inside the LLM attention layers. Other works examine offline semantic rewriting (SAGE) using multi-agent frameworks to remove sensitive identifiers \cite{zhao2027privacy}. However, these approaches do not secure graph relationships or support clearance-level gates. S-RAG focuses on auditing data provenance to detect unauthorized collection but does not prevent runtime inference leakage \cite{zeng2025srag}. Synthetic data generation represents an alternative to mitigate leakage but can degrade context utility \cite{zeng2025mitigating}. Local sandbox tools like EvidenceBot prevent cloud transmissions but do not secure the local database from internal access \cite{khan2025evidencebot}.

\subsection{Graph and Multi-Hop Retrieval}
Knowledge Graph RAG (KG-RAG) improves multi-hop reasoning by traversing structured relationships. However, navigating graph structures leaks structural paths and entity relationships to the database server. While oblivious RAM (ORAM) can hide access patterns, its communication bandwidth scales logarithmically with database size, making it impractical. Bounded-decoy traversal and onion-peeling encryption provide a lighter path to obscure relational navigation. Abstraction Reasoning on Graph (ARoG) anonymizes entities by replacing them with identifiers, but it relies on unencrypted relation chains that expose structural schema details \cite{ning2026privacy}.

\subsection{LLM-Level Security \& Attention Control}
Traditional security models terminate at retrieval: once decrypted, context is loaded in plaintext into the LLM context window. Secure attention control shifts the boundary into the model itself. By keeping context tokens encrypted during transit and only decrypting them inside the self-attention layer using weight-derived subkeys, the system prevents unauthorized intermediate layers from leaking data. Multi-modal extensions evaluate cross-modality leaks, but attention masking remains the core primitive for restricting inference flow \cite{zhang2025beyond}. Knowledge poisoning attacks like PoisonedRAG highlight the vulnerability of attention inputs to corrupted context insertion, reinforcing the need for cryptographic verification of all retrieved tokens prior to generation \cite{zou2025poisonedrag}.

\section{Proposed Methodology / System}
\subsection{System Overview}
The SHIELD-RAG framework is structured around four primary entities: the Client Node, the Key Distribution Center (KDC), the off-chain IPFS payload store, and an EVM-compatible Blockchain index. The ingestion phase begins by extracting text chunks from proprietary documents, which are projected into dense semantic representations using a pre-trained S-BERT model. These embeddings are quantized to integer vectors to support exact algebraic operations. The quantized vectors are projected into low-dimensional signatures using Asymmetric Locality-Sensitive Hashing (ALSH) hyperplanes, and these signatures are subsequently encrypted using searchable functional encryption. The encrypted signatures are registered on-chain in a Solidity smart contract, establishing a secure index. The full quantized embeddings are encrypted and stored off-chain on IPFS under content-addressable hashes (CIDs).

During the query phase, the client encodes the search query, constructs an ALSH signature, and encrypts it to produce a query token. This token is submitted to the blockchain. An off-chain Oracle computes the inner-product similarity matches of the query token against the encrypted document signatures registered on-chain. This matching logic computes the dot products over Paillier ciphertexts without decrypting the signatures. The Oracle returns the CIDs of the top matching documents to the client, logging audit events on the blockchain. Finally, during LLM generation, the client retrieves the encrypted full embeddings from IPFS. These embeddings are passed directly to the LLM attention layers, where they are decrypted and projected on the fly using key blenders and attention gateway subkeys derived from the query-key-value (QKV) weight matrices.

\subsection{Threat Model}
We establish the security boundaries of SHIELD-RAG by defining three distinct trust levels for the participating entities:
\begin{itemize}
    \item \textbf{Trusted Enclave:} The Key Distribution Center (KDC) and the Client Node are trusted. The KDC holds the master secret key ($msk$) and is responsible for safe prime generation, blender distribution, and attention-layer subkey derivation. The client holds the decryption subkeys.
    \item \textbf{Semi-trusted (Honest-but-Curious):} The blockchain validators, database index host, and off-chain matching Oracle are semi-trusted. They execute the mathematical matching protocols correctly, but they attempt to infer query contents, document category domains, and document sensitive levels by observing access patterns or comparing ciphertexts.
    \item \textbf{Untrusted Infrastructure:} The IPFS storage servers and the third-party LLM hosting server are untrusted. They must never observe plaintext queries, document contents, intermediate embeddings, or decrypted self-attention states.
\end{itemize}
The security goals of our system are: (i) Document confidentiality (no storage node can reconstruct documents), (ii) Query privacy (the matching Oracle cannot learn query terms), (iii) Relational path privacy (the database host cannot identify graph navigation links), and (iv) Context containment (unauthorized transient states are blocked at the attention layers).

\subsection{Ada-IPFE Engine}
We implement an optimized searchable IPFE scheme over a Paillier composite modulus. During the setup phase, the KDC selects two large safe primes $p, q$ such that $p = 2p'+1$ and $q = 2q'+1$, where $p', q'$ are also primes. The modulus is computed as $N = pq$, and the order of the cyclic group is $\lambda(N) = 2p'q'$. The KDC generates two system blenders $\alpha, \beta \in \mathbb{Z}_{\lambda(N)}^*$. Given a quantized document vector $\vec{x} \in \mathbb{Z}^d$ and a query vector $\vec{y} \in \mathbb{Z}^d$, the ciphertext $CT_x$ and query key $sk_y$ are constructed as:
\begin{equation}
    CT_x = \left( C_1 = g^{\vec{x}} \bmod N^2, \, C_2 = \alpha \cdot \vec{x} \bmod \lambda(N) \right)
\end{equation}
\begin{equation}
    sk_y = \left( K_1 = \vec{y} \bmod \lambda(N), \, K_2 = \beta \cdot \vec{y} \bmod \lambda(N) \right)
\end{equation}
where $g$ is a generator of the Paillier group. During matching, the untrusted Oracle computes the functional decryption:
\begin{equation}
    D = \prod_{i=1}^d (C_{1,i})^{K_{1,i}} \cdot g^{-\alpha^{-1}\beta^{-1} \langle C_{2}, K_{2} \rangle} \bmod N^2
\end{equation}
Expanding this calculation demonstrates the cancellation of the system blenders:
\begin{equation}
    D = g^{\langle \vec{x}, \vec{y} \rangle} \bmod N^2
\end{equation}
The server solves the discrete logarithm of $D$ to base $g$ using the baby-step giant-step algorithm to recover the similarity score $\langle \vec{x}, \vec{y} \rangle$. Since the blenders $\alpha, \beta$ are held private by the KDC, the server cannot decrypt individual components of the vector.

\subsection{Sensitivity-Embedded IPFE (SE-IPFE)}
To enforce clearance gates at the cryptographic layer, SE-IPFE embeds hierarchical clearance levels. Let $L_d \in \{1, \dots, 5\}$ be the document sensitivity level, and $L_c \in \{1, \dots, 5\}$ be the user clearance level. During query token generation, the client includes their clearance $L_c$. The KDC generates sensitivity-embedded subkeys by injecting an algebraic noise term $\Delta$ based on the clearance gap:
\begin{equation}
    \Delta = r \cdot \max(0, L_d - L_c) \bmod \lambda(N)
\end{equation}
where $r$ is a random salt generated on-fly. The modified decryption key is:
\begin{equation}
    sk_{y,\text{embed}} = sk_y + \Delta
\end{equation}
If $L_c \ge L_d$, the clearance gap is zero, $\Delta = 0$, and the decryption cancels out perfectly to yield $g^{\langle\vec{x},\vec{y}\rangle}$. However, if $L_c < L_d$, the blender cancellation fails:
\begin{equation}
    D = g^{\langle \vec{x}, \vec{y} \rangle + r \cdot (L_d - L_c)} \bmod N^2
\end{equation}
This injects large algebraic noise into the similarity calculation, rendering the discrete logarithm unsolvable and preventing the Oracle from matching or retrieving the document.

\subsection{Query-Derived Cryptographic Scope (QDCS)}
QDCS restricts queries to authorized category scopes. Let $S_q$ be the subspace defined by the query categories, and $P_S$ be the projection matrix onto $S_q$. The projection matrix is computed as $P_S = U U^T$, where $U$ represents the orthonormal basis of $S_q$. The client applies $P_S$ to the query vector before encryption:
\begin{equation}
    \vec{y}_{\text{scope}} = P_S \vec{y}
\end{equation}
For any database document $\vec{x}$ belonging to an out-of-scope category, its representation is orthogonal to $S_q$. The inner product computation yields:
\begin{equation}
    \langle \vec{x}, \vec{y}_{\text{scope}} \rangle = \langle \vec{x}, P_S \vec{y} \rangle = 0
\end{equation}
This forces the similarity score of out-of-scope documents to exactly $0.0$, preventing them from being ranked or retrieved, even if their general semantic vector is highly similar to the query.

\subsection{Progressive Onion Decryption (POD)}
For graph-based retrieval, POD wraps node embeddings in nested layers of Ada-IPFE encryption. Let $D=3$ be the maximum traversal depth. A node embedding $\vec{x}$ is encrypted as:
\begin{equation}
    CT_{\text{onion}} = \text{Enc}_{\text{mpk}_3}(\text{Enc}_{\text{mpk}_2}(\text{Enc}_{\text{mpk}_1}(\vec{x})))
\end{equation}
The public parameters $\text{mpk}_l$ and secret keys $\text{msk}_l$ are independent for each layer $l$. During graph navigation, the client can only decrypt layer $l$ if they have successfully decrypted the parent node in the previous hop, obtaining the required key parameters. If a query attempts to traverse a path without visiting the parent node, the nested decryption fails, keeping the deeper node payload masked under the remaining layers of encryption.

\subsection{Oblivious Bounded-Decoy Graph Traversal}
To prevent the server from learning the traversal path of the client, we implement a bounded-decoy graph traversal mechanism. When navigating to node $v$, the client queries a pre-computed cluster index of S-BERT embeddings to select $K-1$ decoy nodes of the same relation type as $v$. The client creates a shuffled request vector:
\begin{equation}
    \vec{V}_{\text{request}} = \text{Shuffle}(v, d_1, d_2, \dots, d_{K-1})
\end{equation}
The server processes the queries for all $K$ candidates, returning the encrypted payloads. The client filters out the decoy responses locally. The database host only learns that one of the $K$ nodes of the specified relation type was traversed, providing path ambiguity and preventing the reconstruction of the query path.

\subsection{Structured In-Model Decryption}
To secure data during generation, retrieved context tokens are kept encrypted until they reach the LLM self-attention layers. The KDC derives row-wise subkeys for the LLM Query-Key-Value weight matrices $W_Q, W_K, W_V$. During the forward pass, the attention hook decrypts the context tokens:
\begin{equation}
    K_{\text{proj}} = \text{Dec}_{sk_K}(CT_K), \quad V_{\text{proj}} = \text{Dec}_{sk_V}(CT_V)
\end{equation}
The attention computation is modified using the attention mask matrix $M$:
\begin{equation}
    \text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK_{\text{proj}}^T}{\sqrt{d_k}} + M\right)V_{\text{proj}}
\end{equation}
If the relation keys do not authorize a token, the mask entry $M_{ij} = -\infty$, preventing the token from contributing to the generated output.

\section{Implementation \& Experimental Setup}
We evaluate SHIELD-RAG on an Intel Xeon CPU with 64GB RAM. The software is written in Python using PyTorch, SymPy, and the HuggingFace Transformers library. We use a modular architecture containing local files:
\begin{itemize}
    \item \texttt{crypto\_engine.py}: Safe prime generation and baseline functional encryption operations.
    \item \texttt{se\_ipfe\_engine.py}: Access gate sensitivity logic.
    \item \texttt{qdcs\_engine.py}: Subspace projection and orthogonalization.
    \item \texttt{pod\_engine.py}: Onion parameter keys and sequential decryption loops.
    \item \texttt{alsh\_engine.py}: Hashing projections.
    \item \texttt{rag\_pipeline.py}: Secure query matching and self-attention hooks.
\end{itemize}

We utilize SentenceTransformer (\texttt{all-MiniLM-L6-v2}) to encode the \NumDocs\ Wikipedia documents into 384-dimensional dense vectors.
Cryptographic parameters use a Paillier modulus size of 512 bits (256-bit safe primes) for performance benchmarking.
Float quantization uses a scaling factor of $10^4$.
We evaluate:
\begin{itemize}
    \item \textbf{Correctness:} Decryption error tolerance.
    \item \textbf{Latency:} Key generation, encryption, search matching, and gateway decryption times.
    \item \textbf{Accuracy:} Retrieval Hit@10, response relevancy, faithfulness, and correctness.
    \item \textbf{Enforcement:} Security verification under unauthorized clearance, out-of-scope, and multi-hop paths.
\end{itemize}

Transitioning to GPU-parallelized modular arithmetic represents a critical optimization path to support larger corpora.

\subsection{Security and Leakage Analysis}
We analyze how our access control gates protect data from unauthorized leaking. Under standard IPFE, an untrusted Oracle learns the exact similarity scores between a query and all documents, allowing the construction of user search profiles. Under SE-IPFE, unauthorized clearance levels prevent similarity score computations completely, converting the output of the decryption function into high-entropy algebraic noise. Similarly, QDCS projects out-of-scope document matches to exactly $0.0$, preventing leakage from out-of-scope queries. For POD, graph node payloads are only unmasked if the traversal sequence is correctly followed, ensuring that the database host cannot extract the contents of distant nodes in the graph topology.

\subsection{Latency and Throughput Trade-offs}
Evaluating the system reveals a latency-security trade-off. Standard RAG operates at millisecond scale but offers zero privacy. Operating functional encryption over 512-bit safe prime composite fields increases database search time to \AdaSearchLatency\ for 385 documents on CPU. SE-IPFE and QDCS maintain this latency without overhead, but wrapping vectors in three onion layers (POD) increases search time to \PodSearchLatency\ due to sequential decryptions. In-model attention gateway decryption introduces \GatewayDecTime\ per attention block, representing a practical trade-off for protecting transient context states during LLM generation.

\section{Conclusion and Future Work}
We presented SHIELD-RAG, a unified privacy-preserving hybrid RAG framework. By combining searchable functional encryption with sensitivity-embedded keys, orthogonal category scopes, and progressive onion decryption, the system secures vector search, graph navigation, and prompt generation. Our evaluation on \NumDocs\ documents shows near-plaintext search accuracy with complete data confidentiality. Future work will investigate GPU acceleration for Paillier modular exponentiations and scale the evaluation to larger corpus sizes.
